* flex-x

~flex-x~ is an Emacs completion style built on the built-in ~flex~
completion style.

* Features

- Built-in flex matching before whitespace is entered, switching to
  order-independent literal AND filtering after whitespace.
- Sort by minibuffer history, then flex match quality.
- Force flex-quality sorting in fuzzy mode, including for completion tables
  which request an ~identity~ sort function.
- Preserve completion metadata sorting in literal mode.
- Highlight matches with standard completion faces.
- Add a regexp expander for non-ASCII candidates, for example migemo or pyim.

* Setup

~flex-x~ is available from [[https://melpa.org/#/flex-x][MELPA]].  After enabling the MELPA
package archive, install and configure it with ~use-package~.  The
~icomplete-minibuffer-setup-hook~ binding mirrors the current ~init.org~
configuration used for the screenshots:

#+begin_src emacs-lisp
  (use-package icomplete
    :ensure nil
    :init
    (fido-vertical-mode))

  (use-package flex-x
    :ensure t
    :config
    (add-hook 'icomplete-minibuffer-setup-hook
              (lambda ()
                (setq-local completion-styles '(flex-x basic))))

    (setopt completion-styles '(flex-x basic)))
#+end_src

In Fido completion minibuffers, ~SPC~ runs ~minibuffer-complete-word~ instead
of inserting a space.  This means that pressing ~SPC~ after fuzzy input may
replace the input with the candidates' common prefix, which can consist only
of indentation.  Use ~C-q SPC~ to insert an occasional literal space and
switch flex-x to literal matching.

If whitespace-separated filtering is used frequently, bind ~SPC~ to
~self-insert-command~.  The optional ~M-SPC~ binding below keeps word
completion available on another key:

#+begin_src emacs-lisp
  (with-eval-after-load 'icomplete
    (keymap-set icomplete-fido-mode-map
                "SPC" #'self-insert-command)
    (keymap-set icomplete-fido-mode-map
                "M-SPC" #'minibuffer-complete-word))
#+end_src

Some completion categories have built-in ~completion-category-overrides~
which can prepend or replace styles for that category. If you want
~flex-x~ to be preferred for those categories too, configure category
overrides explicitly:

#+begin_src emacs-lisp
  (setopt completion-category-overrides
          '((buffer (styles . (flex-x basic substring)))
            (project-file (styles . (flex-x substring)))))
#+end_src

For migemo-style matching, pass ~migemo-get-pattern~ directly:

#+begin_src emacs-lisp
  (with-eval-after-load 'migemo
    (setq flex-x-extra-pattern-function #'migemo-get-pattern))
#+end_src

For pyim-style matching:

#+begin_src emacs-lisp
  (with-eval-after-load 'pyim
    (require 'pyim-cregexp-utils nil t)
    (setq flex-x-extra-pattern-function #'pyim-cregexp-build))
#+end_src

By default, expanded regexp matching is used only for candidates containing
non-ASCII characters. Customize ~flex-x-extra-match-nonascii-only~ if
you want it to run for every candidate.

Before whitespace is entered in the active completion field, the input uses
built-in flex matching.  After whitespace is entered, every non-empty term must
match as a literal substring or through the configured regexp expander.  Terms
may occur in any order.  Input containing only whitespace does not filter
candidates.

In fuzzy mode, flex-x always sorts both display and cycle candidates by match
quality.  An explicit non-identity metadata sort function is retained and
determines the order of candidates with equal flex quality.  An ~identity~ sort
function is intentionally overridden so fuzzy results are never left
unranked.

In literal mode, flex-x does not add flex-quality or history sorting.  Original
display and cycle sort functions, including ~identity~, are preserved.  A
trailing space can therefore be used both to request literal matching and to
restore a completion table's original ordering.

When minibuffer completion does not provide an explicit sort function, flex-x
first sorts by flex match quality and then stably promotes matching candidates
from the active minibuffer history.  Candidates outside the history keep their
flex order.  Explicit metadata sort functions and completion outside the
minibuffer do not receive this history promotion.

Expanded regexp matching scans up to ~flex-x-extra-match-candidate-limit~
raw candidates for the current completion prefix. The default limit is
~5000~; when it is exceeded, flex-x stops predicate-driven enumeration
and skips regexp expansion. Set it to nil if you want migemo or
pyim expansion to scan every candidate even in very large completion
tables. Ignored filename extensions are filtered after regexp expansion,
so an ignored file remains available when it is the only match.

** Corfu History Sorting

Corfu normally uses a completion table's ~display-sort-function~ instead of
~corfu-sort-function~.  Since flex-x provides a display sort function, enabling
~corfu-history-mode~ alone does not combine Corfu history sorting with flex-x
sorting.  Use the
[[https://github.com/minad/corfu/wiki#combined-sorting][combined sorting configuration from the official Corfu wiki]]
to apply both:

#+begin_src emacs-lisp
  (with-eval-after-load 'corfu
    (corfu-history-mode 1)

    (defun my-corfu-combined-sort (candidates)
      "Sort CANDIDATES using both display and Corfu sort functions."
      (let ((candidates
             (let ((display-sort-function
                    (corfu--metadata-get 'display-sort-function)))
               (if display-sort-function
                   (funcall display-sort-function candidates)
                 candidates))))
        (if corfu-sort-function
            (funcall corfu-sort-function candidates)
          candidates)))

    (setopt corfu-sort-override-function #'my-corfu-combined-sort))
#+end_src

This makes Corfu history sorting the final sorting layer.  Since
~corfu-sort-override-function~ deliberately overrides completion metadata, it
also reorders literal-mode results whose ~display-sort-function~ is ~identity~.
Omit this override where preserving the completion table's exact order in
literal mode is more important than Corfu history sorting.

* Regexp Expander

~flex-x-extra-pattern-function~ can be nil, one function, or one function
name. The function receives a search term and should return a regexp string or
nil.

Examples:

#+begin_src emacs-lisp
  (setq flex-x-extra-pattern-function #'migemo-get-pattern)
#+end_src
